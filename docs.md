# Документация API — Мониторинг конкурентов

> Область применения: локальный веб- и Windows-desktop инструмент для одного/нескольких
> доверенных пользователей (например, владелец кофейни и его команда на одном ПК/в одной сети).
> Интерфейс и тексты ответов модели — на русском языке. Аутентификации и разграничения прав
> доступа нет — не предназначено для развёртывания в публичном интернете или для недоверенных
> пользователей.

### Где хранится история

- Запуск из исходников (`python run.py`): `history.json` в корне проекта (можно переопределить `HISTORY_FILE`).
- Desktop-сборка (exe): `%APPDATA%\CompetitionMonitor\history.json` — вне каталога сборки,
  переживает пересборку/переустановку exe.
- Формат — обычный JSON-файл **без шифрования** (plaintext): последние `MAX_HISTORY_ENTRIES`
  запросов, включая полные тексты/результаты анализа. Любой, у кого есть доступ к файловой
  системе/учётной записи пользователя, может прочитать историю. Это осознанный компромисс для
  локального инструмента; не храните в нём данные, которые нельзя хранить в открытом виде на диске.
- Запись атомарна (temp-файл + `os.replace`), защищена внутрипроцессной блокировкой; повреждённый
  файл истории не перезаписывается молча — переименовывается в `history.corrupt-<timestamp>.json`
  для дальнейшего разбора, а работа продолжается с пустой историей.

### Что уходит на сторону OpenAI

`/analyze_text`, `/analyze_image`, `/analyze_url` и `/parse_demo*` отправляют содержимое запроса
(введённый/извлечённый из PDF текст, изображение в виде base64, скриншот страницы и извлечённый
текст страницы) в **официальный OpenAI API** (`api.openai.com`) для анализа. Сторонние
OpenAI-совместимые эндпоинты (Groq/OpenRouter/Ollama и т.п.) сознательно не поддерживаются — в
`Settings` нет такой настройки, и `base_url` клиента OpenAI SDK **явно закреплён** на
`https://api.openai.com/v1` при каждом создании клиента (`backend/services/openai_service.py:
get_openai_client`). Это не просто отсутствие настройки: сам SDK, если `base_url` не передан
явно, по умолчанию подставляет значение из переменной окружения `OPENAI_BASE_URL`, если она
задана в процессе, — явное закрепление гарантирует, что эта переменная окружения не может
незаметно перенаправить клиент на сторонний хост. Это осознанное ограничение области применения
проекта, а не провайдер-абстракция. Отправляемый текст
обрезается до `MAX_AI_TEXT_CHARS` символов (по умолчанию 12000) — это касается текста из
`/analyze_text`, а также title/h1/первого абзаца, извлечённых парсером в `/parse_demo*`
(каждое поле обрезается независимо). Скриншоты сайтов и загруженные изображения передаются
целиком (в пределах `MAX_IMAGE_BYTES`/размера скриншота). Каждый вызов OpenAI использует
таймаут `OPENAI_TIMEOUT` явно — он не может незаметно откатиться к отличающемуся значению
по умолчанию SDK.

## 3. Формат ответов и ошибок

Успешный ответ соответствует конкретной Pydantic-схеме эндпоинта (см. `backend/models/schemas.py`
и `/openapi.json` — это источник истины); ad-hoc обёртки вида `{"success": ..., "data": ...}`,
добавленные поверх схемы, в API не используются. Это не значит, что каждый ответ — плоский объект
без вложенности: там, где вложенный объект — часть самой схемы ответа, он присутствует как есть,
например `/analyze_url` возвращает `{"url": "...", "analysis": {...}}` (модель `AnalyzeUrlResponse`),
а `/parse_demo` — `{"url": ..., "title": ..., "h1": ..., "first_paragraph": ..., "analysis": {...}}`
(модель `ParsedContent`); см. примеры в разделе 5.

**Ошибки** возвращаются реальным HTTP-статусом (не 200 с полем `error` внутри), с телом
`{"error": "безопасное сообщение"}` — с двумя исключениями, оба — стандартное поведение
FastAPI/Starlette, а не что-то, реализованное этим приложением:
- **422** (валидация Pydantic от FastAPI) — тело `{"detail": [...]}`.
- **400** от собственной проверки Starlette на количество полей/файлов multipart-формы
  (`Request.form(max_fields=..., max_files=...)`, см. §4) — если она срабатывает раньше, чем
  код эндпоинта успевает выполниться, ответ формирует сам Starlette с телом
  `{"detail": "Too many fields...."}` / `{"detail": "Too many files...."}`, а не наш
  `AppError`-обработчик с телом `{"error": ...}`. Остальные 400-и (в т.ч. небезопасный/
  недопустимый URL, слишком короткий текст) идут через `AppError` и используют `{"error": ...}`
  как обычно.

Текст `error` для непредвиденных ошибок (500) всегда обобщённый и не содержит деталей
исключения — полная информация (traceback) пишется только в серверный лог.

| Код | Когда |
|-----|-------|
| 400 | Некорректный вход: слишком короткий текст, небезопасный/недопустимый/неразобираемый URL (включая некорректный порт и некорректное/слишком длинное имя хоста — см. §4 «Политика безопасности URL»), отсутствуют URL конкурентов, недопустимый заголовок `Host` (см. §7), а также аномальное число полей/файлов multipart-формы (см. выше), и т.п. |
| 403 | Запрос с браузерным заголовком `Origin`, не относящимся к этому приложению (см. §7). |
| 413 | Превышен лимит размера **входных данных запроса к этому API** (текст/PDF/изображение/тело запроса) — не то, что вернул сторонний сайт (см. 502 ниже). |
| 415 | Неподдерживаемый тип содержимого (не PDF/не изображение по сигнатуре файла, не text/html и т.п.). |
| 422 | Ошибка валидации тела запроса (стандартный механизм FastAPI/Pydantic). |
| 503 | Не задан `OPENAI_API_KEY` / некорректный ключ, либо Selenium недоступен/не установлен. |
| 502 | Сбой на стороне OpenAI (включая отказ по фильтру содержимого, пустой/некорректный структурированный ответ) или целевого сайта (upstream) — включая ответ удалённого сайта, превышающий `MAX_REMOTE_RESPONSE_BYTES` (это ошибка со стороны сайта-конкурента, не входных данных клиента этого API, поэтому классифицируется как 502, а не 413). |
| 504 | Таймаут запроса к OpenAI или к целевому сайту (httpx или Selenium). |
| 500 | Непредвиденная внутренняя ошибка (сообщение обобщённое, детали — в логах сервера). |

Ошибки Selenium (webdriver/браузер) клиенту всегда возвращаются как одно из нескольких
стабильных обобщённых сообщений — никогда сырой текст исключения (который может содержать
локальные пути, внутренние детали драйвера и т.п.); полная информация для диагностики
пишется только в серверный лог в момент сбоя.

`/parse_demo/batch` — исключение: это пакетная операция, и ошибка по одному URL из списка не
приводит к отказу всего запроса — она отражается как элемент `results[i].error` (200 в целом,
если сама операция выполнена).

## 4. Лимиты и безопасность входных данных

| Настройка | По умолчанию | Что ограничивает |
|-----------|--------------|-------------------|
| `MAX_TEXT_CHARS` | 20000 | Текст в `/analyze_text` (после извлечения из PDF, если есть) |
| `MAX_PDF_BYTES` | 15 МБ | Загружаемый PDF-файл (после парсинга multipart — см. ниже) |
| `MAX_PDF_PAGES` | 50 | Страниц в PDF |
| `MAX_PDF_EXTRACTED_CHARS` | 50000 | Текст, извлечённый из PDF |
| `MAX_IMAGE_BYTES` | 8 МБ | Загружаемое изображение |
| `MAX_REQUEST_BODY_BYTES` | 20 МБ | Тело запроса `/analyze_text` — JSON-путь: реально ограничивает объём **прочитанных байт** (потоковое чтение с проверкой на каждый чанк), а не только заявленный `Content-Length` (который может отсутствовать или быть недостоверным) |
| `MAX_REMOTE_RESPONSE_BYTES` | 5 МБ | Ответ стороннего сайта: для httpx — точный лимит байт тела ответа; для Selenium — приблизительный символьный лимит на `page_source` (см. ниже, «Selenium: границы обработки») |
| `MAX_AI_TEXT_CHARS` | 12000 | Текст, отправляемый в OpenAI за один вызов: текст из `/analyze_text`, и независимо — title/h1/первый абзац из `/parse_demo*` (каждое поле обрезается своим лимитом) |

Загружаемые файлы проверяются **по сигнатуре содержимого** (магическим байтам), а не только по
расширению/заголовку `Content-Type` — несовпадение возвращает 415.

### Multipart (`/analyze_text` с PDF): что именно ограничено

Starlette разбирает `multipart/form-data` **до** того, как код эндпоинта получает управление,
поэтому у приложения нет возможности вставить собственную потоковую проверку размера в процессе
разбора без написания своего multipart-парсера (сознательно не делается — см. ниже). Реально
действующие ограничения:

- `Content-Length` проверяется до чтения тела (быстрый отказ 413), когда заголовок присутствует
  и превышает `MAX_REQUEST_BODY_BYTES`.
- Запрос разбирается с `max_fields=8, max_files=1` (`Request.form(...)`, встроенный механизм
  Starlette) — форма с аномальным количеством полей/файлов отклоняется 400 на этапе разбора,
  до вызова кода эндпоинта; тело ответа в этом случае — стандартное `{"detail": "..."}` от
  самого Starlette, а не наш `{"error": ...}` (см. §3).
- После разбора файл `file` читается **повторно, ограниченными чанками** и обрывается с 413 при
  превышении `MAX_PDF_BYTES` (см. `backend/limits.py:read_upload_limited`).
- **Известное ограничение:** сам факт разбора multipart-тела Starlette выполняет до вызова этого
  кода — клиент, отправляющий файл без корректного `Content-Length` (например, chunked-запросом
  собственного изготовления, не через обычный браузер/curl -F), теоретически может заставить
  сервер принять и буферизовать/сплошировать на диск файл большего размера, чем `MAX_PDF_BYTES`,
  прежде чем последующая проверка его отклонит. Для локального доверенного инструмента это
  принятый остаточный риск (см. §11 корректирующего прохода); реализация полноценного
  потокового byte-cap поверх стороннего multipart-парсера сознательно не делается.

### Selenium: границы обработки

Selenium не даёт перехватывать сетевой уровень браузера (см. также §4 «Политика безопасности
URL» ниже) — `MAX_REMOTE_RESPONSE_BYTES` для Selenium-пути не является точным сетевым лимитом,
как для httpx. Вместо этого сразу после получения `driver.page_source` эта строка обрезается до
`MAX_REMOTE_RESPONSE_BYTES` символов, прежде чем передаётся в BeautifulSoup и далее — это
ограничивает объём **обработки на стороне приложения** (и, следовательно, объём title/h1/текста,
которые в принципе могут попасть в OpenAI — независимо от этого их дополнительно обрезает
`MAX_AI_TEXT_CHARS`), а не объём данных, которые сам браузер успел скачать по сети.

### Политика безопасности URL (SSRF-защита)

Общая для httpx- и Selenium-путей (`backend/services/url_safety.py`): разрешены только
`http`/`https` (схема сравнивается без учёта регистра — `HTTP://…` равнозначно `http://…`), URL с
логином/паролем (`user:pass@host`) отклоняются, хост обязан разрешаться по DNS, и ни один из
полученных IP не должен быть loopback/приватным/link-local/multicast/reserved/unspecified
(проверяется для IPv4 и IPv6). Некорректный порт (`http://host:bad/`, вне диапазона 0–65535 и
т.п.) отклоняется как 400, а не приводит к 500 — включая путь логирования: `redact_url()`
(используется для безопасного логирования URL, в том числе внутри обработчиков ошибок) сама
никогда не бросает исключение на некорректном URL. Для httpx-запросов каждый редирект проверяется
заново перед тем, как за ним последовать — публичный URL, ведущий редиректом на приватный адрес,
отклоняется. Это базовая защита для локального инструмента, а не полноценная сетевая песочница;
для Selenium проверяется только начальный адрес (Selenium не даёт управлять редиректами постранично)
— **поддерживаются только доверенные/публичные URL конкурентов**, не произвольные недоверенные ссылки.

## 5. Примеры запросов

### 5.1. POST /analyze_text

Тело — **либо** JSON `{"text": "..."}` (минимум 10 символов), **либо** `multipart/form-data` с
необязательным полем `text` и/или файлом `file` (PDF).

```bash
curl -X POST "http://127.0.0.1:8000/analyze_text" \
  -H "Content-Type: application/json" \
  -d '{"text": "Наша кофейня открылась в 2020 году, авторские напитки, 3 точки в городе."}'
```

**Ответ (200):**

```json
{
  "strengths": ["Опыт на рынке", "Авторские напитки"],
  "weaknesses": ["Нет информации о ценах"],
  "unique_offers": ["Авторские напитки"],
  "unique_selling_points": [],
  "recommendations": ["Добавить цены и адреса точек"],
  "summary": "Небольшая сеть кофеен с авторским меню.",
  "content_quality": 6,
  "price_category": ""
}
```

### 5.2. POST /analyze_image

`multipart/form-data`, поле `file`. Разрешены (по сигнатуре файла): JPEG, PNG, GIF, WebP.

```bash
curl -X POST "http://127.0.0.1:8000/analyze_image" -F "file=@banner.jpg"
```

**Ответ (200):**

```json
{
  "description": "Скриншот главной страницы кофейни",
  "marketing_insights": ["Акцент на уют и локальность"],
  "visual_style_score": 7,
  "visual_style_analysis": "Тёплая цветовая палитра, минимализм.",
  "recommendations": ["Добавить кнопку онлайн-заказа выше сгиба"],
  "design_score": 7,
  "animation_potential": false,
  "menu_visibility": 4,
  "brand_style": "уютный, локальный",
  "usability_score": 6,
  "content_quality": 6
}
```

### 5.3. POST /parse_demo

```json
{ "url": "https://example.com" }
```

**Ответ (200):**

```json
{
  "url": "https://example.com",
  "title": "Example Domain",
  "h1": "Example Domain",
  "first_paragraph": "Текст первого абзаца...",
  "analysis": {
    "strengths": [],
    "weaknesses": [],
    "unique_offers": [],
    "unique_selling_points": [],
    "recommendations": [],
    "summary": "...",
    "content_quality": 3,
    "price_category": ""
  },
  "error": null
}
```

Если контент извлечь не удалось (таймаут/недоступность) — ответ **502** (или 504 при таймауте) с
телом `{"error": "..."}`, а не 200.

### 5.4. POST /parse_demo/batch

Без тела запроса — использует `COMPETITOR_URLS` из настроек.

```bash
curl -X POST "http://127.0.0.1:8000/parse_demo/batch"
```

**Ответ (200):**

```json
{
  "results": [
    { "url": "https://example.com", "title": "...", "h1": "...", "first_paragraph": "...", "analysis": { "...": "..." }, "error": null },
    { "url": "https://unreachable.example", "title": null, "h1": null, "first_paragraph": null, "analysis": null, "error": "Не удалось извлечь контент." }
  ],
  "total": 2
}
```

Если `COMPETITOR_URLS` пуст — **400** `{"error": "В настройках нет URL конкурентов..."}`.

### 5.5. POST /analyze_url

Требуется установленный Chrome (Selenium Manager сам подбирает подходящий драйвер).

```json
{ "url": "https://example.com" }
```

**Ответ (200):**

```json
{
  "url": "https://example.com",
  "analysis": {
    "summary": "Краткое резюме анализа сайта.",
    "design_score": 7,
    "usability_score": 6,
    "content_quality": 6,
    "unique_selling_points": ["Подарок при заказе двух напитков"],
```

## 6. Таймауты

| Настройка | По умолчанию | Что покрывает |
|-----------|--------------|-----------------|
| `PARSER_CONNECT_TIMEOUT` | 10 с | Установка соединения с целевым сайтом (httpx) |
| `PARSER_TIMEOUT` | 30 с | Чтение ответа целевого сайта (httpx) / общий таймаут загрузки страницы (Selenium) |
| `MAX_REDIRECTS` | 5 | Число HTTP-редиректов, которым следует httpx-парсер |
| `OPENAI_TIMEOUT` | 60 с | Один вызов OpenAI (структурированный анализ) — применяется одинаково во всех путях: `/analyze_text`, `/analyze_image`, `/analyze_url`, `/parse_demo*` |

`PARSER_CONNECT_TIMEOUT`/`MAX_REDIRECTS` — настройки httpx-пути: доходят до фактического
httpx-запроса в `/parse_demo` (первичный парсинг) и `/parse_demo/batch` — не только у функции с
настройками по умолчанию. На Selenium-навигацию они не влияют: ни на `/analyze_url` (Selenium без
httpx), ни на `/parse_demo*` при `PARSER_USE_SELENIUM=true`, ни на автоматический Selenium-повтор
`/parse_demo` (см. ниже). `MAX_REMOTE_RESPONSE_BYTES` как сетевой лимит (точный лимит байт тела
ответа) тоже применяется только к httpx-пути; для Selenium она используется иначе — как
приблизительный символьный лимит уже загруженного `page_source`, ограничивающий объём
последующей обработки, а не саму сетевую загрузку (см. §4 «Selenium: границы обработки»).

`/analyze_url` использует Selenium напрямую, без предварительного httpx-запроса: `PARSER_TIMEOUT`
передаётся как есть в качестве таймаута загрузки страницы Selenium
(`driver.set_page_load_timeout`). Автоматического повтора через Selenium здесь нет и не может
быть — httpx в этом эндпоинте не используется вовсе.

`/parse_demo` изначально использует httpx-путь (если `PARSER_USE_SELENIUM` не включён) с таймаутом
чтения `PARSER_TIMEOUT`. Если httpx вернул таймаут либо скудный контент (title+h1+первый абзац
суммарно короче 100 символов), выполняется автоматический повтор через Selenium — уже с таймаутом
`min(PARSER_TIMEOUT + 15, 60)` секунд, а не с `PARSER_TIMEOUT` напрямую; из-за этого повтора
итоговое время ответа может быть выше таймаутов, указанных по отдельности.

`/parse_demo/batch` парсит каждый URL тем же способом, что и начальный вызов `/parse_demo` (httpx
или Selenium — в зависимости от `PARSER_USE_SELENIUM`), но без автоматического повтора через
Selenium при таймауте/скудном контенте — этот повтор есть только у одиночного `/parse_demo`.

## 7. Сеть, CORS и локальная браузерная защита

- Веб-сервер по умолчанию слушает только `127.0.0.1` (см. `API_HOST` в `.env.example` для
  осознанного LAN-доступа — без аутентификации, только в доверенной сети). Desktop-режим всегда
  на `127.0.0.1`, независимо от настроек.
- CORS выключен по умолчанию: `/static` и API отдаются одним и тем же процессом (один origin).
  Включается явно через `CORS_ALLOW_ORIGINS`, только если фронтенд обслуживается отдельно.
- **Заголовок Host и same-origin проверка** (`backend/local_guard.py`) — сервис локальный и без
  аутентификации, поэтому loopback-привязки самой по себе недостаточно (браузер на этой же
  машине может быть спровоцирован обратиться к серверу через DNS rebinding, либо страница с
  постороннего сайта может отправить сюда fetch()-запрос — CORS лишь не даёт браузеру
  *прочитать* такой ответ, но не мешает запросу выполниться на сервере). На каждый запрос:
  - заголовок `Host` должен называть `localhost`/`127.0.0.1`/`::1` (порт не важен — desktop-режим
    каждый раз выбирает свободный порт) либо значение, явно заданное через `API_HOST`; иначе — 400;
  - для запросов, изменяющих состояние (не GET/HEAD/OPTIONS), заголовок `Origin`, если он
    присутствует, должен совпадать с origin самого запроса (тот же host, что и в `Host`) либо
    входить в `CORS_ALLOW_ORIGINS`; иначе — 403. Запрос без заголовка `Origin` (curl, прямые
    API-клиенты) по-прежнему разрешён — это защита от браузерных сценариев, не аутентификация.

## 8. Desktop-конфигурация (exe)

`.env` **никогда** не упаковывается в PyInstaller-дистрибутив (проверяется тестом
`tests/test_packaging.py` и regression guard'ом в `competitionmonitor.spec`, который рекурсивно
обходит содержимое каждого каталога, добавленного в `datas` — включая `backend/`/`static/` и
всё, что подмешивает `collect_all()`, — а не только имя самой записи `datas`). Настройте:

- переменную окружения ОС `OPENAI_API_KEY` (и при необходимости другие из `.env.example`), либо
- файл `%APPDATA%\CompetitionMonitor\.env` — живёт вне каталога сборки, переживает пересборку/
  переустановку exe.

Сборка — **папка-дистрибутив (onedir)**, не единый exe-файл: `competitionmonitor.exe` в папке
`competitionmonitor/` рядом со своими зависимостями (`_internal/` и т.д.). Требуется установленный
Chrome в системе — Selenium Manager (входит в пакет `selenium`) сам подбирает и скачивает
подходящий драйвер при первом запуске, отдельно устанавливать chromedriver не нужно.
